Manual de uso — AUTO OFERTAS

Sistema de gestión de la playa de autos. Multi-sucursal: clientes, vehículos, ventas, cuotas, cobranzas y flujo de caja.

Contenido: 1. Login · 2. Dashboard · 3. Vehículos · 4. Clientes · 5. Ventas · 6. Cuotas · 7. Cobrar · 8. WhatsApp · 9. Caja · 10. Casos comunes · 11. Atajos

1. Entrar y salir

Tipeá usuario y contraseña. Tras 5 errores en un minuto, el sistema bloquea unos minutos.

Para salir: clic en el círculo con tu inicial (arriba a la derecha) → Cerrar sesión.

2. Dashboard

Resumen del negocio: Vehículos (total + disponibles), Ventas del período, Cobrado del período, Cartera vencida.

Barra lateral: 📊 Dashboard · 🚗 Vehículos · 💰 Ventas · 👥 Clientes · 📋 Cuotas · 💵 Flujo de caja · ⚙️ Usuarios (solo admin).

Arriba al medio: selector de sucursal (filtra todas las pantallas). Arriba: filtro de fechas con quick ranges (Este mes / Mes anterior / Este año / Año anterior).

3. Cargar un vehículo

Vehículos → + Nuevo vehículo (solo admin).

Obligatorios: Marca, Modelo, Año, VIN (único), Precio + Moneda (PYG/USD), FOB / Container / Despacho / Cam-Vol (poner 0 si no se conocen).

Opcionales: Patente, color, kilometraje, conceptos extras de costo (flete, patente, honorarios, etc.), descripción.

💡 El costo total = FOB + Container + Despacho + Cam-Vol + extras (calculado automáticamente).

4. Cargar un cliente

Clientes → + Nuevo cliente.

Obligatorios: Nombre, Apellido, Tipo de doc (CI/RUC/Pasaporte), N° documento (único en la empresa).

Recomendados: Teléfono (necesario para WhatsApp), Email, Ciudad, Dirección, Notas.

⚠ Si el documento ya existe el sistema avisa con error. Buscá y editá en lugar de duplicar.

5. Registrar una venta

Ventas → + Nueva venta.

  1. Cliente: buscalo por nombre/doc/teléfono. Si no existe, "+ Nuevo cliente" sin perder los datos.
  2. Vehículo: del stock disponible (o crear uno).
  3. N° de venta: CM/26-001 (Cerrada) o MC/26-001 (Mixto). Si dejás vacío queda ??/26-001.
  4. Fecha, Forma de pago (Contado/Crédito/Mixto), Entrega inicial si aplica.

6. Plan de cuotas

Desde Ventas → ícono 📋 de la fila → modal "Cuotas de la venta CM/26-XXX".

Sección "Generar plan de cuotas": cantidad, 1er vencimiento, monto por cuota (autocalculado), nombre del plan (opcional) → 🎯 Generar preview.

Verificá: suma cuadra con (total − seña), fechas correctas. → 💾 Guardar cuotas.

⚠ Si ya hay cuotas y querés agregar más, escribí encima del modelo "Cuotas existentes".

7. Cobrar cuota

Dos caminos: desde el modal de cuotas de la venta o desde el detalle del cliente.

En la fila de la cuota → 💵 Pagar → modal:

Completá fecha de pago, forma (Efectivo / Transferencia / Caja / Acuerdo), nota opcional → Confirmar pago.

💡 El cobro genera automáticamente el movimiento de ingreso en flujo de caja.

Desde Clientes → click en el cliente: ves todo su historial.

8. WhatsApp

En el detalle del cliente o en cada cuota: botón verde 💬 WhatsApp. El sistema:

  • Normaliza el teléfono a formato internacional (0981... → 595981...).
  • Arma el mensaje pre-formateado:
    "Buen día Juan, le recordamos la cuota N°3 con vencimiento 15/05/2026 por Gs. 1.500.000. Cualquier consulta estamos a las órdenes. AUTO OFERTAS."
  • Abre WhatsApp Web/app con el mensaje listo. Solo apretás enviar.
⚠ Cliente sin teléfono → el botón no aparece. Editar primero.

9. Flujo de caja

Tres KPIs: Ingresos (verde), Egresos (rojo), Saldo neto. La tabla lista cada movimiento del período. Los "⚙ auto" (cobros de cuotas, señas, ventas contado) NO se borran a mano — se ajustan cambiando la venta/cuota de origen.

Movimientos manuales: + Nuevo movimiento.

Tipos: Cobro de cuota / Venta contado / Seña / Pago a cuenta / Gasto / Alquiler / Sueldo / Comisión / Compra al exterior / Transporte / Impuesto / Ajuste / Otro. Dirección: Ingreso (verde) o Egreso (rojo). Proveedor opcional (AUTOWINI, DADANI, etc.).

10. Casos comunes a resolver

El panel "Datos a revisar" del dashboard linkea a cada categoría de inconsistencia. Los chips arriba de cada listado (Ventas, Clientes, Vehículos) filtran rápido por tipo de problema.

10.1. Cuotas vencidas sin pagar

Detectar: KPI rojo "Cartera vencida" del dashboard, panel "Clientes morosos" (top 15), o filtrar Cuotas por estado = Vencidas.

Acción:

  1. Contactar al cliente con 📱 WhatsApp (mensaje pre-formateado).
  2. Si pagó → 💵 Pagar → registrar cobro.
  3. Si pidió posponer → editar la cuota cambiando el vencimiento.
  4. Si no responde tras 2-3 intentos → anotar en notas del cliente y considerar acción legal.
⚠ NO marques pagada una cuota sin recibir el dinero. Rompe el flujo de caja y los reportes.

10.2. Ventas sin cliente o sin vehículo

Detectar: chips "⚠ Sin cliente" y "⚠ Sin vehículo" arriba de Ventas.

Arreglar: editar la venta (✏) → buscar/crear el cliente o vehículo real → Guardar.

💡 Si no sabés quién compró (migración vieja), dejar "Cliente General" o crear uno temporal hasta aclarar con el papelerío físico.

10.3. Ventas con código MIG

Ventas importadas de la planilla Excel vieja (MIG-001, MIG-2018-XX). Si están cerradas y cobradas, dejarlas. Si tienen datos incompletos, completar. Para renombrar al formato actual CM/26-001: editar → "N° de venta".

⚠ NO borrar en masa. Muchas tienen cuotas pendientes de cobro reales.

10.4. Venta con monto incorrecto o cero

Síntomas: Total en Gs. 0, total negativo, o total que no coincide con la suma de las cuotas.

Detectar: chip "⚠ Placeholder" en Ventas marca las que tienen total=0 o ??/YY de número.

Arreglar:

  1. Editar la venta → completar el campo Precio unitario con el monto real.
  2. Si tiene entrega inicial, completar Entrega inicial (seña).
  3. Guardar.
  4. Si la venta ya tenía cuotas: abrir el modal de cuotas → borrar las viejas → regenerar el plan con los montos correctos (las cuotas NO se recalculan solas al cambiar el total).

10.5. Venta "Cerrada" pero sin cobros (a crédito sin cuotas)

Síntomas: En la tabla de Ventas, la columna Cobranza dice "Sin cobros aún 0/0" en una venta marcada como Cerrada (que debería tener un plan).

Causas típicas:

  • Venta a crédito donde nunca se generó el plan de cuotas.
  • Migración importó la venta pero las cuotas quedaron en otra tabla.

Arreglar: abrir el modal de cuotas (📋) → generar el plan (sección 6 del manual). Si el cliente ya pagó algo, marcar esas cuotas como cobradas con la fecha real del pago.

10.6. Venta a contado pero con plan de cuotas (inconsistencia)

Síntomas: venta con Forma de pago = Contado y a la vez tiene cuotas generadas.

Arreglar: decidir cuál es lo correcto:

  • Si era contado real → entrar al modal de cuotas y borrarlas todas. El cobro contado ya está registrado como movimiento de caja al cerrar la venta.
  • Si era a crédito mal cargada → editar la venta → cambiar Forma de pago a "Crédito" (o "Mixto" si hubo seña) → Guardar.

10.7. Vehículo "Vendido" pero sigue "Disponible" (o viceversa)

Detectar: en Vehículos, buscar el VIN. Estado debería coincidir con la situación real de la venta.

Causas: venta cancelada sin liberar el vehículo, o venta a crédito en estado "Reserva" que nunca pasó a "Cerrada".

Arreglar: abrir la venta → cambiar el Estado (Reserva → Cerrada o Cancelada según corresponda) → Guardar. El sistema sincroniza el estado del vehículo automáticamente al cambiar el estado de la venta.

⚠ Si tenés que editar el estado del vehículo directamente (sin pasar por la venta), hacelo desde Vehículos → Editar → Estado. Pero verificá que coincida con la venta para no romper reportes.

10.8. Cuotas que no cuadran con el total de la venta

Síntomas: al abrir el modal de cuotas, la suma de las cuotas existentes ≠ (total − seña).

Causas: alguien editó el monto de la venta a posteriori, o alguien tocó montos individuales de cuotas.

Arreglar:

  1. Verificar cuál es el monto real (contrato físico o lo que el cliente está pagando).
  2. Si lo correcto es el plan de cuotas → editar la venta y ajustar el Precio unitario.
  3. Si lo correcto es el monto de la venta → borrar las cuotas y regenerar el plan.

10.9. Cuota pagada por error / pago duplicado

Síntomas: una cuota figura como Cobrada pero el cliente dice que no pagó, o aparecen dos movimientos de cobro de la misma cuota.

Arreglar:

  1. Editar la cuota → cambiar Estado de "Cobrada" a "Pendiente" → borrar fecha de pago → Guardar.
  2. Ir a Flujo de caja → buscar el movimiento auto generado por ese cobro → si quedó duplicado, borrar el manual (los auto no se borran, se regeneran solos).
⚠ Anotar el motivo del cambio en las notas de la cuota para que el audit log tenga contexto.

10.10. Vehículos con VIN basura o sin precio

Chips de calidad en Vehículos: "⚠ Sin precio" (price = 0) y "⚠ VIN placeholder" (VIN-DUMMY, VIN12345). Editar y completar con datos reales.

10.11. Clientes con documento autogenerado

Docs tipo DRV026-001, SUC026-XXX, CUOTA-XX son placeholders de la migración. Chip "⚠ Doc autogenerado" los filtra. Cuando consigas la cédula real, editar el cliente.

💡 Funcionan perfecto igual; el doc placeholder es solo cosmético. No es urgente.

10.12. Clientes sin teléfono

Chip "⚠ Sin teléfono". Sin él no se puede mandar WhatsApp. Pedí el número cuando venga el cliente.

10.13. Clientes duplicados (mismo nombre, distinto documento)

Detectar: tipear el nombre en la búsqueda de Clientes — si aparecen 2+ fichas con el mismo nombre, hay duplicado.

Arreglar:

  1. Elegir cuál es la ficha "buena" (la que tiene más ventas o datos más completos).
  2. Para las ventas/cuotas de la ficha duplicada: editar cada una → reasignar al cliente bueno.
  3. Una vez sin ventas asociadas, borrar el duplicado.
⚠ Confirmar que sean la misma persona física antes de mergear. Dos clientes con mismo nombre pueden ser personas distintas (parentesco, homónimos).

10.14. Nombre y apellido invertidos

A veces se carga "PEREZ JUAN" en Nombre y vacío en Apellido (o viceversa). En reportes el formato queda raro.

Arreglar: editar el cliente → mover el apellido al campo correcto → Guardar.

10.15. Venta con vendedor / sucursal mal asignados

Pasa cuando el vendedor cargó la venta desde la sucursal equivocada o se olvidó de elegir vendedor.

Arreglar: editar la venta → cambiar el campo Sucursal y/o Vendedor → Guardar. Las comisiones y reportes por sucursal se actualizan automáticamente.

10.16. Fecha de venta incorrecta (futuro o muy vieja)

Síntomas: venta con fecha 01/01/1900, fechas futuras (ej. 2099), o fechas muy lejanas a cuando ocurrió realmente.

Arreglar: editar la venta → cambiar Fecha de venta al valor real. Esto NO afecta las cuotas (sus vencimientos quedan como están), pero sí afecta los reportes de "Ventas por período".

10.17. Borraste algo por error

El sistema tiene audit log de todas las acciones (crear/editar/borrar). Para pérdidas críticas: contactar al admin → tenemos backups semanales restaurables.

10.18. Cuando no estás seguro

Si encontrás una inconsistencia pero no sabés cómo arreglarla, NO improvices:

  1. Anotá en las notas del cliente o venta: qué viste, fecha, qué te dijo el cliente.
  2. Marcá la venta con un código tipo REVISAR en N° de venta para que sea fácil de filtrar después.
  3. Avisá al admin/dueño para que tome la decisión.
💡 Es preferible una venta con "dato pendiente" anotado que una venta editada con un dato inventado. El audit log preserva la historia, pero un cambio mal hecho puede romper los reportes.

11. Atajos y tips

Ctrl + K — Buscador global

Buscador transversal en ventas, clientes y vehículos. Tipeá N° de venta, nombre, VIN, marca → resultado → ir directo.

Selector de sucursal

Si hay 2+ sucursales, el selector arriba del navbar filtra todos los reportes. Por usuario (no afecta a otros).

Filtros de período

Dashboard, Ventas, Flujo de caja tienen filtro desde/hasta con quick ranges. Solo afecta lo que ves, no toca los datos.

Backups

Automáticos semanales (lunes 03:00 UTC). Manual: python scripts/backup_db.py. Quedan en backups/snapshot_<fecha>.json.gz, NO se suben a GitHub.

Si algo no funciona

  • Una página no carga: F5. Si sigue mal, logout + login.
  • Error 401: sesión venció, login otra vez.
  • No deja crear: leer el mensaje rojo arriba del form.
  • Ayuda: contactar al admin del sistema.
